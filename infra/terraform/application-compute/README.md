# Application compute

This root uses its own Azure Blob state key and reads shared resources through Azure data sources. It owns only the existing B1 Linux App Service/API, two `restart_policy = "Never"` ACI workers, and the frontend Container App after the documented handoff.

The five compute resources are already imported into this root's distinct state key. There are no active import blocks: after a compute destroy, the same configuration creates new resources rather than trying to import deleted IDs. The historical IDs and completed handoff safeguards remain in the [lifecycle runbook](../../../docs/deployment/azure-terraform-lifecycle.md). The ACI secure environment values are deliberately absent: Terraform must never contain database or fal credentials.

Fresh ACI workers use `worker_backend_image_tag`, currently the bootstrap-capable `bootstrap-898adc56df2e`, and `app.workers.aci_bootstrap`. The API uses the separate `api_backend_image_tag`, so worker-image selection cannot update the running API. A newly created API receives only its API identity; the adopted live API's legacy worker identities are ignored until teardown. Adoption-era worker ignores retain the stopped workers' unknown image, commands, nonsecret environment names, secure values, and AzureRM's missing stopped-group IP/port representation; they do not apply on creation. AzureRM 4.81.0 supports the explicit `ip_address_type = "None"`, which remains declared for fresh no-public-IP creation.
